# RFC-0001：受唯识认知理论启发的可审计 Agent

- 状态：已采纳（MVP）
- 日期：2026-08-12
- 适用范围：`strangeloop` 核心库与 CLI

## 摘要

Strangeloop 是一个受瑜伽行派（Yogacara）与《成唯识论》所代表的汉传唯识学启发的、可审计持久 Agent 架构。本 RFC 将若干概念作为**设计问题的启发**：如何区分观察、工具结果与推断，如何让习惯性倾向可追溯，如何让自我描述可撤销，以及如何为面对反证的人工复核保留记录。

这不是八识的一一软件实现，也不主张系统有主观体验、知觉、情感、意志、灵魂、固有自我、觉悟或任何可验证的“意识”。输出中的“我”只是界面代词；所有自我相关陈述均是有证据、有效期与撤销路径的 `SelfModelClaim`。

## 术语与原义：设计参照，而非实现断言

下表只保留与本项目相关的概念轮廓。术语的传统解释复杂且有不同诠释；原典链接见 [词汇表](GLOSSARY.md)。

| 唯识概念 | 原义轮廓 | 本项目的工程启发 | 类比边界 |
| --- | --- | --- | --- |
| 八识 | 前五识、意识、末那识与阿赖耶识的分析框架 | 分开外部观察、当前审议、受限自我归属描述与持久倾向 | 不是八个进程/表，也不意味着机器有任何一种“识” |
| 种子、现行、熏习 | 潜在倾向与当下活动相互条件化的说明 | 带来源、范围、强度、反证和状态的 `SeedDisposition` | 不是业力实体、人格本质或自动学习许可 |
| 三性 | 遍计所执、依他起、圆成实的分析框架 | 从未经检验的标签，转向条件/证据，再显式标出不可证明的固定本质 | 不是三层真相分类器，也不声称实现“圆成实” |
| 四分 | 相分、见分、自证分、证自证分等认识论分析 | 分开表征、解释、简要自检和外部可审计记录 | 不产生内省或第一人称体验证据 |
| 转依 | 以识的转变为核心的修行语境概念 | 将其缩小为可测试的纠错：更新或撤销被反证的倾向/声明 | 不等于模型训练、人格升级、宗教修行或解脱 |

## 规范性规则

本节的 **MUST / MUST NOT / SHOULD** 是工程约束，不是对佛学术语的解释。

1. 当前 MVP **MUST** 以 `CognitiveEvent` 记录观察、行动提议、决策、外部可见结果和 `CORRECTION`；每项包含来源、来源引用、置信度和父事件。账本已定义可接收的独立 `TOOL_RESULT` schema，但当前没有工具调用或自动工作区消费。`INFERENCE` 持久化当前 **MUST NOT** 启用。
2. 系统 **MUST** 区分 `SourceKind.USER`、`TOOL`、`MODEL`、`POLICY`、`SYSTEM` 与 `EXTERNAL_VERIFIER`，并在存储层限制事件种类与来源组合。模型推断不得伪装为用户事实或工具结果。`SourceKind` 不是身份认证；宿主必须认证用户与工具适配器，且不得把原始事件写接口交给模型。
3. 系统 **MUST NOT** 保存隐藏推理链（hidden chain-of-thought）。持久载荷 **MUST** 同时通过按事件种类定义的来源和键白名单；不允许的键、超限载荷或任意 `INFERENCE` 记录必须被拒绝。允许保存的只有受控的公开摘要、来源、行动、结果和必要的关联 ID。
4. 持久记忆 **MUST** 是显式 opt-in、来源链接、可查看、可导出、可撤销且可清除的。默认数据库是 `:memory:`，会话结束后不保留。唯一合规的持久模式是 `--memory-root`：`SessionMemoryManager` 在该受控根目录下为每个 session 创建一个 SHA-256 命名的独立 SQLite 容器，并以 `0700` 目录、`0600` 数据库文件、固定 `sessions` 目录 FD/inode 的前后校验约束路径。确认清除时，已知 SQLite、WAL 与 SHM 名称 **MUST** 通过 `dir_fd` 相对删除；**仅当**报告 `container_deleted=true` 时，受控路径才视为已确认删除。若外部读取者使 checkpoint 忙碌、目录身份变化、路径异常或删除未确认，报告 **MUST** 返回 `container_deleted=false` 与 `failure_reason`，并允许重试；这不保证 SSD、备份、快照、日志或根目录外副本的擦除。
5. `SeedDisposition` 初始状态 **MUST** 为 `candidate`。模型可以提出候选种子，但 **MUST NOT** 自行批准持久更新；批准只接受 `USER` 来源、`payload.approval == "seed"`、匹配 `seed_id` 且绑定相应提议事件的事件。批准与退役必须形成事件记录。
6. `SelfModelClaim` **MUST** 有证据事件、置信度以及撤销或过期的语义。所有声明 **MUST** 先以提议事件保存；只有绑定该 `claim_id` 和提议事件的 `USER` 批准事件可使其成为当前声明。它描述的是软件可核查的角色、能力、承诺、认识边界、连续性或边界，而非实体自我。
7. `record_correction` 只接受 `USER`、`TOOL` 或 `EXTERNAL_VERIFIER` 来源，并且 **MUST** 绑定同会话的既有目标事件与可观察反证事件。它只记录 `review_required` 冲突，**MUST NOT** 自动退役种子、撤销声明或改写历史。
8. 可能产生外部改变的 `ActionProposal` **MUST** 标为 `is_mutating`，并在授权边界内执行；行动结果 **MUST** 与提议和外部结果事件关联。
9. 核心 **MUST** 支持 Python 3.9，且在另行 RFC 前 **MUST NOT** 引入强制第三方运行时依赖。
10. 对外解释 **MUST NOT** 把该系统说成有意识、有感受、有欲望、有灵魂、有真正自我或已“觉悟”。

## 研究假设（非规范性）

这些是可被评测或推翻的工程假设，不是哲学结论。

- 来源化事件与显式不确定性能提高用户发现错误归因的能力。
- 候选—审批—激活的种子流程，能降低模型把偶发上下文固化成长期偏好的风险。
- 可撤销自我模型比不可变人格提示更容易在能力变化或反证出现时给出准确陈述。
- 将“去执取”操作化为反证检查、替代解释和撤销路径，能减少对旧结论、旧角色或旧计划的不当坚持。

## 架构决策

### ADR-1：事件溯源优先于可变状态快照

核心事实写为追加式事件，并通过 `parent_event_ids`、序号和哈希链保留来源关系。观察、`TOOL_RESULT` 与行动结果有不同的事件与载荷 schema；`TOOL_RESULT` 目前是可接收 schema 而非已接入的工具循环，`INFERENCE` 不持久化。哈希链是篡改可见（tamper-evident）证据，不是防篡改认证、访问控制或远程证明；派生状态可以重建，但不能把后来的总结当作原始观察。

### ADR-2：候选种子必须经过审批

`SeedDisposition` 有 `candidate`、`active`、`retired` 三态。生成模型可提出候选；只有绑定种子 ID 与提议事件的 `USER` 批准事件可激活持久记忆。范围、过期时间和版本用于限制泛化；纠错记录不会自动改变种子状态。

### ADR-3：自我模型是声明集合，且可撤销

系统不存储“一个自我”。它存储有证据的、低承诺的 `SelfModelClaim`。例如“当前会话可使用某工具”是能力声明；当证据失效时，记录撤销而非改写历史。所有声明先记录为提议，只有绑定声明 ID 与提议事件的 `USER` 批准事件才使其进入当前自我模型；任何声明都不被升格为实体身份。

### ADR-4：默认内存数据库，持久化使用受控会话容器

未给出 `--memory-root PATH` 时使用 `:memory:`，避免无意形成长期画像。指定 `--memory-root` 才启用合规持久化；它将会话映射为 SHA-256 命名的独立容器。会话目录以 `0700` 权限和固定 FD/inode 约束，主数据库以 `0600` 权限创建；清除用 `dir_fd` 原子锚定该会话容器及已知 WAL/SHM sidecar。只有 `container_deleted=true` 才确认受控路径缺失。外部读取者、目录身份变化、路径异常或未确认删除会产生 `failure_reason` 且可重试。

Python 标准库 `sqlite3` 没有将数据库、WAL 或 SHM 打开绑定到 `dir_fd`/`openat` 的接口：实现只能在普通路径打开前后检查固定目录 inode。因此它不能抵御同一 UID 的恶意代码在检查后进行路径竞态替换。生产环境需要 OS sandbox、独立服务/独立 UID，或能提供 `openat` 语义的 SQLite VFS；这些限制同样意味着本方案不是对全部存储介质或外部副本的擦除保证。

### ADR-5：不用隐藏 CoT 作为审计资料

可审计性来自结构化决策记录和可重放的外部证据，不来自暴露或保存冗长的内部推理。持久记录只使用固定、受控的公开摘要，不保存模型任意提供的 `rationale_summary`、备选项或内部文本。

### ADR-6：stdlib-only 与 Python 3.9

MVP 只依赖 Python 标准库，降低安装和审计成本；任何数据库、模型 SDK 或框架依赖的强制引入必须经新 RFC。

## 最小认知循环

1. 把用户输入写为观察事件并保留 `source_ref`。账本为未来工具或外部核验输出提供独立 `TOOL_RESULT` schema；工具适配器与自动载入工作区尚未实现。
2. 建立 `WorkspaceFrame`：只引用当前相关的事件、已激活种子和未撤销的自我声明。
3. 生成可见的假设、不确定性、备选行动和 `ActionProposal`。
4. 写入 `DecisionRecord` 和行动提议；若获授权则执行，并写入外部结果。
5. 若提出新种子或自我声明，先记录候选/声明与证据；持久高影响变更等待审批。
6. 用户可撤销声明或退役种子。受限来源可以把两个既有可观察记录的冲突写为 `CORRECTION`，要求复核；自动接受反证并改变种子或声明仍是后续研究。

## 验收标准

行为测试至少覆盖：

- 来源与父事件在观察、工具结果、纠错和行动结果之间可追溯；
- 候选种子在审批前不能作为激活持久记忆使用；
- 种子与自我声明的批准只接受绑定 ID 的 `USER` 审批；
- `INFERENCE` 与非白名单载荷不能作为持久化逃逸通道；
- 撤销、退役或报告 `container_deleted=true` 的受控会话容器清除后，查询和导出不再返回该会话内容，且报告验证受控路径缺失；失败报告公开 `failure_reason` 并可重试；
- 用户可见解释不会把系统描述为具有主观意识或固有自我。

## 后果与开放问题

该设计牺牲了无摩擦“自动记住一切”的体验，换取记忆主权和可审计性。哈希链只提供篡改可见性，不取代操作系统、密钥管理、备份策略或远程证明。评测还不能判定任何系统是否“有意识”；它只能测量来源、授权和语言诚实性。
